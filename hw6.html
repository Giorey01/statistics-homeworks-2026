Homework 6 · Integration theory and special functions

Riemann vs. Lebesgue, and the normal CDF

1. Two ways to cut an area

Riemann partitions the domain: vertical strips, each as high as a value of f. Lebesgue partitions the range: horizontal slabs, each as wide as the set of points where f exceeds that level.

Riemann sum

Sn = Σi f(ξi)·(xi − xi−1)

Partition a = x0 < … < xn = b, one tag ξi per cell. Using the inf (sup) of f on each cell gives the lower (upper) Darboux sum L ≤ Sn ≤ U. f is Riemann-integrable when U − L → 0.

Lebesgue sum

Σk yk·μ({x : yk ≤ f(x) < yk+1})

Levels y0 < … < yM, μ = Lebesgue measure (length). This is the integral of a simple function below f; its error is at most Δy·μ(domain). Equivalently, the layer-cake formula below.

∫ f dμ = y0·(b − a) + ∫y0y1 μ({x : f(x) > t}) dt   (layer cake: integrate in the height t the measure of the set above t)

When does each one work?

Lebesgue's criterion: a function on [a, b] is Riemann-integrable if and only if it is bounded and its set of discontinuities has measure zero. Every Riemann-integrable function is also Lebesgue-integrable and gives the exact same value, so on all standard, well-behaved functions the two approaches always agree. The converse is not true: Lebesgue can integrate functions that are discontinuous everywhere (like the Dirichlet function) because sets of measure zero simply do not contribute to the integral. It also handles unbounded functions like 1/√x without needing a separate theory of improper integrals. In probability theory, Lebesgue integration is essential because it allows swapping limits and integrals under dominated convergence, which is why expectations E[X] are defined as Lebesgue integrals.

From definition to algorithm

Computing a Riemann sum on a computer is straightforward: I sample f at n points and sum the rectangles. A Lebesgue sum is harder to compute directly because I need the measure of the preimage {x : f(x) > t}. Here I test two numerical approaches:

  • Lebesgue (exact pre-images): I split [a, b] at points where f changes direction or has jumps. On each monotone piece, {f > t} is just an interval, and I find its boundary using bisection. I then approximate the integral over the range using M levels. Lower and upper Darboux–Lebesgue sums give a guaranteed bracket for the true value.
  • Lebesgue (sampled pre-images): I sample f at N points, sort the values into M bins, and count how many points fall into each bin. This works for any function without knowing its structure, but since it relies on an x-grid, it is essentially a Riemann sum in disguise.

4. Pathological functions: where the two disagree

4.1 Dirichlet: 1 on the rationals, 0 elsewhere

Riemann. Every cell of every partition contains both rationals and irrationals, so inf f = 0 and sup f = 1 on each cell: L = 0 and U = 1 for every partition. A Riemann sum takes any value between 0 and 1 depending on the tags (all rational → 1, all irrational → 0). It does not converge, so f is not Riemann-integrable (it is discontinuous everywhere, a set of measure 1).

Lebesgue. ℚ ∩ [0, 1] is countable. Cover its k-th element by an interval of length ε/2k+1: the total length is below ε, and ε is arbitrary, so μ(ℚ) = 0. With the two levels 0 and 1: ∫ f = 1·μ(ℚ) + 0·μ([0, 1] \ ℚ) = 0. The table builds this cover explicitly for all rationals with denominator ≤ Q.

Why this cannot be tested directly on a computer. Every IEEE-754 double-precision float is stored as a fraction m / 2k, meaning it is always rational. A literal isRational(x) check would return true for every floating-point number, giving an incorrect sum of 1. The table below shows the exact fractions stored by the machine for familiar numbers:

To test Dirichlet, I track rationality symbolically: a tag is rational when constructed as a fraction (like the midpoints (2i + 1)/(2n)), and irrational when shifted by an irrational offset (like rational + √2·h). From a probabilistic point of view, picking a random number in [0, 1] hits a rational with probability μ(ℚ) = 0, so Monte Carlo simulation gives 0.

4.2 Thomae: f(p/q) = 1/q, f(irrational) = 0

Thomae's function is continuous at every irrational and discontinuous at every rational. Because the rationals have measure zero, it is Riemann-integrable and both methods give 0. However, the way Riemann sums converge to 0 depends on the arithmetic of n. Using grid tags i/N, f(i/N) = gcd(i, N)/N (computed with exact integers).

Riemann sums with tags i/N for N = 1 … 600. Primes sit on the lower envelope (≈ 2/N, where every tag yields 1/N except f(0) = 1). Highly composite values of N form upper spikes.

Lebesgue. For any threshold t > 0, {f > t} = {p/q : q < 1/t} is a finite set, with measure 0. Every term of the Lebesgue sum vanishes, giving an exact value of 0 for any number of levels M.

4.3 A fat Cantor set: an indicator Riemann cannot integrate

While Dirichlet cannot be simulated directly with floats, the Smith–Volterra–Cantor set C can be built algorithmically. I start with [0, 1] and at each step k remove an open interval of length 1/4k from the middle of each remaining piece. The total length removed is Σ 2k−1/4k = ½, so the remaining set has measure μ(C) = ½, even though it contains no intervals at all (it is nowhere dense). For the indicator function 1C:

  • every cell contains a removed gap → inf = 0 → L = 0;
  • the upper sum counts the cells that meet C. Because C is closed, U → μ(C) = ½;
  • U − L → ½ ≠ 0: not Riemann-integrable (discontinuous on all of C, a set of measure ½);
  • Lebesgue: ∫ 1C = μ(C) = ½, directly.

5. The normal CDF and the error function

For Z ~ N(0, 1) (Hogg, McKean, Craig, §3.4):

φ(t) = e−t²/2 / √(2π),     Φ(x) = P(Z ≤ x) = ∫−∞x φ(t) dt,     P(X ≤ x) = Φ((x − μ)/σ) for X ~ N(μ, σ²)

The definite integral over the whole line can be computed exactly. Squaring it and switching to polar coordinates, I² = ∫∫ e−(x²+y²)/2 dx dy = ∫02π∫0∞ e−r²/2 r dr dθ = 2π, so ∫φ = 1. The antiderivative, however, cannot be written in elementary terms (§6). Symmetry gives Φ(0) = ½ and Φ(−x) = 1 − Φ(x).

The error function

erf(z) = (2/√π) ∫0z e−s² ds,    erfc(z) = 1 − erf(z)
Φ(x) = ½·(1 + erf(x/√2)) = ½·erfc(−x/√2)

Proof: Φ(x) = ½ + ∫0x φ(t) dt. Substituting t = s√2 (dt = √2 ds) gives ∫0x φ = (1/√π)∫0x/√2 e−s² ds = ½·erf(x/√2). This gives an exact analytical relationship. However, erf is just a standard name given to this integral (like sin and exp are names for other functions); writing erf(x) does not compute its value directly.

6. Why Φ is not elementary: Liouville's theorem

Elementary functions are those built from rational functions, exp and log (hence roots, trigonometric functions and their inverses) through finitely many arithmetic operations and compositions.

Theorem (Liouville, 1835, special case)

Let f, g be rational functions, g non-constant. Then ∫ f(x) eg(x) dx is elementary if and only if there is a rational function R with f = R′ + R·g′. In that case, the antiderivative is R(x)·eg(x).

For e−x²: f = 1, g = −x², g′ = −2x. An elementary antiderivative would need a rational R with

R′(x) − 2x·R(x) = 1.
  • R a polynomial of degree d ≥ 0: −2xR has degree d + 1 while R′ has degree d − 1, so the left side has degree d + 1 ≥ 1 and cannot equal the constant 1. (R = 0 gives 0 ≠ 1.)
  • R with a pole of order k ≥ 1 at some point a: R′ has a pole of order k + 1 there, −2xR at most of order k, so the left side still has a pole at a, while 1 has none.

No such R exists, so ∫ e−x² dx is not elementary, and neither is Φ (it is the same integral rescaled). The same argument shows that Si(x) = ∫ sin x / x and Ei(x) = ∫ eˣ / x are not elementary either. The general theory is the Risch algorithm (1969), in Rosenlicht's algebraic formulation (1972).

Saying that Φ is not an elementary function does not mean it does not exist or that it cannot be computed. Because the normal density φ is continuous, Φ is well-defined everywhere and can be approximated to any precision needed. It simply means there is no finite closed formula built from standard operations.

7. Why numerical methods are still needed, and which ones

Writing Φ(x) in terms of erf(x/√2) gives an exact formula on paper, but erf still has to be computed numerically. Even standard functions like Math.exp and Math.sin are computed using polynomial or rational approximations in the math library, since the processor only does +, −, ×, ÷, and √. JavaScript does not even have a built-in Math.erf, so I had to implement Φ myself. A good implementation needs three things: high precision (~10−16) across the whole line, accurate relative error in the tails (where values like 10−10 need correct digits), and fast evaluation.

Method Formula Strengths / weaknesses
Simpson Φ(x) = ½ + ∫0x φ, n = 64 Error O(h⁴) on a smooth integrand. Computes ½ − (almost ½) in the tail, so all relative accuracy is lost there.
Taylor series of erf erf z = (2/√π) Σ (−1)ⁿ z2n+1 / (n!(2n+1)) Converges for every z, but the alternating terms grow to about ez² before cancelling. Accurate for |x| ≲ 3.
Positive series (A&S 7.1.6) Φ(x) = ½ + φ(x)·(x + x³/3 + x⁵/(3·5) + …) All terms share one sign, so the sum has no cancellation (this is Marsaglia's 2004 method). Still ½ − (almost ½) in the left tail.
Asymptotic expansion Φ(−a) ≈ φ(a)/a·(1 − 1/a² + 3/a⁴ − 15/a⁶ + …) Divergent, but truncated at its smallest term it is excellent for a ≳ 6. The first term gives the Mills-ratio bound. Useless near 0.
Continued fraction (Laplace) Φ(−a) = φ(a) / (a + 1/(a + 2/(a + 3/(a + …)))) Converges for every a > 0, quickly for large a. Computes the small tail directly.
A&S 26.2.17 / 7.1.26 Φ(−a) ≈ φ(a)·P₅(t), t = 1/(1 + 0.2316419a) Rational approximations with 5 fixed coefficients and one exp. Very fast, with absolute error < 7.5·10⁻⁸ (1.5·10⁻⁷ for 7.1.26), but relative error in the tail is poor.
Hybrid (mine) a = |x|: a < 1.4 → series; a ≥ 1.4 → continued fraction Computes the small tail Q = Φ(−a) directly, then sets Φ(x) = Q for x ≤ 0 and 1 − Q for x > 0. Like Cody's 1969 SPECFUN algorithms, this switches approximations across intervals to preserve relative precision.

My implementation

const phi = (x) => Math.exp(-0.5 * x * x) / Math.sqrt(2 * Math.PI);

function tail(a) {                       // Q(a) = Φ(−a) = 1 − Φ(a), a ≥ 0
  if (a < 1.4) {                         // positive series
    let term = a, sum = a;
    for (let k = 3; term > 1e-17 * sum; k += 2) sum += (term *= a * a / k);
    return 0.5 - phi(a) * sum;
  }
  let d = a;                             // continued fraction, bottom-up
  for (let k = Math.ceil(15 + 500 / (a * a)); k >= 1; k--) d = a + k / d;
  return phi(a) / d;
}

const Phi = (x) => (x <= 0 ? tail(-x) : 1 - tail(x));

The tail trap: catastrophic cancellation

Evaluating the upper tail as 1 − Φ(x) subtracts two numbers close to 1, inducing catastrophic cancellation. In IEEE-754 double precision, Φ(x) rounds to 1 for x ≳ 8.3, entirely erasing significant tail digits. Applying Gaussian symmetry resolves the issue: P(Z > x) = Φ(−x) computes the small tail directly.

9. Conclusions

Riemann and Lebesgue

On all standard Riemann-integrable functions, both approaches converge to the exact same value, as expected from the theory. The main differences are how fast they converge and how much they cost to compute:

  • Accuracy and convergence. Riemann sums depend on how smooth f(x) is: Simpson's rule reaches order 4 on smooth curves like sin x. Lebesgue integration depends instead on the smoothness of the level-set measure t ↦ μ({f > t}). Flat peaks or valleys in f slow Lebesgue down to order 1.5 because of square-root singularities in the measure (as in sin x). On the other hand, infinite slopes do not hurt the measure, which is why Lebesgue keeps order 2 on √x while Riemann drops to 1.5.
  • Computational cost. In practice, measuring preimages exactly requires numerical root-finding (around 50 function calls per piece using bisection). This makes exact Lebesgue integration roughly two orders of magnitude more expensive per step than a simple Riemann sum. The sampled histogram version runs at standard Riemann speed, but adds quantization error from binning values.
  • Pathological and difficult functions. For unbounded functions like 1/√x, Lebesgue integration works naturally with a simple height truncation, while standard Riemann sums fail at x = 0. For functions with discontinuities on a set of positive measure (Dirichlet, Fat Cantor), Riemann sums never converge (U − L > 0), whereas the Lebesgue integral gives the correct area directly. On Thomae's function, both reach 0, but Riemann sums oscillate with the arithmetic of N.
  • Implementation considerations. Because computers use discrete floating-point numbers, they cannot detect irrational numbers or find arbitrary preimages on their own. Numerical Lebesgue integration either requires knowing the shape of f in advance, or using Monte Carlo methods (which estimate measures directly because P(X ∈ A) = μ(A)).

The normal CDF

Liouville's theorem shows that Φ cannot be written with standard elementary functions. While the error function erf provides a clean mathematical definition, numerical methods are still needed to evaluate it. Each method has trade-offs: Taylor and Marsaglia series converge fast near 0, but fail in the tails because subtracting two nearly equal numbers destroys precision. Continued fractions and asymptotic expansions do the opposite: they work best in the far tails. Fixed rational approximations (Abramowitz & Stegun) are very fast, but stop around 10−7 accuracy. Combining a series near 0 with a continued fraction in the tails (my hybrid approach) gives double precision everywhere (~10−16) with sub-microsecond runtimes.
