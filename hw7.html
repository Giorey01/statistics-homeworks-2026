1. The bivariate dataset (X, F)

"Bivariate" means that each statistical unit k = 1 … n carries two observations, the pair (xk, fk). Both variables here are categorical: X has r categories a1 … ar (they become the rows of the table), F has c categories b1 … bc (the columns).

The assignment says "any" dataset, so the page offers three: a synthetic one and two real ones. The synthetic one continues the hacker story of HW4–HW5 and acts as a control: since we wrote the generator, we know the right answer and can check that the test finds it. Two more synthetic models, one independent and one weakly dependent, are not in the menu: §8 uses them to measure the type I error and the power of the test.

  • Synthetic, dependent: X = hacker level, F = outcome, and seniors succeed much more often than juniors.
  • Real, Titanic: 2201 people on board, class × survival.
  • Real, NSL-KDD: 25192 network connections, protocol × traffic class (normal, DoS, probe, R2L/U2R).

The seed fixes the random generator (mulberry32), so the same seed always gives the same data. Change it to see a new random sample from the same model.

Numeric variables need binning. A contingency table needs categories. A numeric variable, such as the 0–10 score of HW5, has to be cut into classes first, for example [0, 3), [3, 7), [7, 10]. The cut points change χ², so they must be stated and justified. The datasets here are categorical from the start, so no binning is needed.

2. Contingency table

The contingency table counts the pairs: nij = number of units with X = ai and F = bj. Adding a row gives the row total ni· = Σj nij (how many units have X = ai, whatever F); adding a column gives the column total n·j. The dot stands for "summed over that index". All the totals add up to n.

How the code builds it

It is a "group by and count". First the categories are fixed (one index per category, kept in a Map), then a single loop over the n pairs adds one to the right cell. The cost is O(n + r·c). 

function crossTab(xs, fs, rows, cols) {
  rows = rows || [...new Set(xs)];        // categories of X, in order of appearance
  cols = cols || [...new Set(fs)];        // categories of F
  const ri = new Map(rows.map((v, i) => [v, i])),
        ci = new Map(cols.map((v, j) => [v, j]));
  const table = rows.map(() => cols.map(() => 0));
  for (let k = 0; k < xs.length; k++) table[ri.get(xs[k])][ci.get(fs[k])]++;
  return withTotals(rows, cols, table);   // adds rowTot, colTot, n
}

3. Marginal and conditional frequencies

Counts are hard to compare when the rows have different sizes (there are many more juniors than seniors). Dividing by the right total turns them into proportions. Which total you divide by decides what the proportion means.

Joint

fij = nij / n

share of all units in cell (i, j). Sums to 1 over the whole table.

Marginal

fi· = ni·/n,   f·j = n·j/n

distribution of one variable alone, ignoring the other. Written in the margins of the table, hence the name.

Conditional

f(bj | ai) = nij/ni·

distribution of F among the units with X = ai only ("given X = ai"). Each row sums to 1: the row profile. Swapping roles gives the column profile f(ai | bj) = nij/n·j.

The three are linked by the empirical version of P(A ∩ B) = P(B | A) P(A):  fij = f(bj | ai)·fi· = f(ai | bj)·f·j.

Joint relative frequencies, with the marginals

Row profiles f(F | X)

Read one row at a time: "among the juniors, which share failed, partially succeeded, succeeded?". The last row is the marginal of F: the same question asked of everybody.

Column profiles f(X | F)

Read one column at a time: "among the successful attacks, which share came from juniors, mids, seniors?".

100% stacked bars

One bar per row profile, plus the marginal of F at the bottom. If X and F were independent, every bar would break at the same points as the marginal (the dashed lines). Bars that break elsewhere are the visible sign of dependence.

4. Expected frequencies under independence

Suppose X and F are independent. Then the share of units in cell (i, j) should be the share with X = ai times the share with F = bj, exactly as P(A ∩ B) = P(A)·P(B) for independent events. Multiplying by n gives the count we expect in that cell:

Eij = n · fi· · f·j = n · (ni·/n) · (n·j/n) = ni· · n·j / n     ("row total × column total ÷ grand total")

  • Eij is usually not an integer: it is an average, not a count that can really be observed.
  • The expected table has the same margins as the observed one (Σj Eij = ni··Σj n·j/n = ni·). It keeps how many juniors and how many successes there are, and only redistributes them as if the two variables had nothing to do with each other.
  • Cochran's rule: the χ² approximation used in §6 is trusted when no Eij is below 1 and at most 20% of them are below 5. With small n (try n = 30) the rule fails; then merge categories or use the permutation test, which does not need it.

5. The χ² statistic

We now have two tables, the observed Oij = nij and the expected Eij. Pearson's χ² (1900) turns their difference into a single number:

χ² = Σi Σj (Oij − Eij)² / Eij,    df = (r − 1)(c − 1),    V = √(χ² / (n·(min(r, c) − 1)))
  • Square: so that positive and negative deviations do not cancel out (Σ (O − E) is always 0, because both tables have the same total).
  • Divide by E: a deviation of 10 is huge in a cell where we expect 5 and nothing in a cell where we expect 5000. For a count with mean E the natural random spread is about √E (Poisson: variance ≈ mean), so (O − E)/√E is a standardized residual, and χ² is the sum of their squares.
  • χ² ≥ 0, and χ² = 0 only if O = E in every cell, i.e. if the table is exactly independent.
  • Degrees of freedom df = (r − 1)(c − 1): once the margins are fixed, you can choose the cells of the first r − 1 rows and c − 1 columns freely, and the last row and column are forced by the totals. A 2×2 table has df = 1; a 3×3 has df = 4.

Where the dependence is: residual heatmap

χ² says whether the table deviates from independence, the residuals rij say where and in which direction. On the dependent dataset: juniors fail more than expected and seniors succeed more than expected.

Cramér's V: the strength of the association

χ² grows with n. If every count is doubled the proportions do not change, but χ² doubles. With a huge n even a negligible dependence gives a huge χ². To measure how strong the association is, χ² is divided by its largest possible value, n·(min(r, c) − 1), and the square root is taken: this is Cramér's V, between 0 (independent) and 1 (one variable determines the other). For a 2×2 table it equals the φ coefficient. Rough guide (Cohen): for a 2×2 table 0.1 small, 0.3 medium, 0.5 large; for bigger tables divide these thresholds by √(min(r, c) − 1), so for a 3×3 table they become 0.07, 0.21, 0.35. 6. The p-value

Even when X and F are truly independent, a random sample never gives χ² = 0 exactly: the counts are integers and fluctuate by chance. The question is whether the observed χ² is larger than chance alone would usually give. We set up a test:

  • H0 (null hypothesis): X and F are independent in the population, pij = pi··p·j.
  • H1: they are not.
  • p-value = P(χ² ≥ χ²observed | H0): the probability, if H0 were true, of a deviation at least as large as the one we saw. If p < α (here α = 0.05) we reject H0.

To compute p we need the distribution of χ² under H0. Pearson (with the right df found by Fisher in 1922) showed that for large n it is approximately the χ² distribution with df degrees of freedom, the distribution of a sum of df squared independent standard normals. The p-value is its right tail. JavaScript has no such function, so the page implements it three ways and also estimates p without any formula.

df = 1: reuse Φ of HW6

χ²₁ = Z² with Z ~ N(0, 1), so p = P(|Z| ≥ √x) = 2·Φ(−√x). Φ(−a) is the small tail computed in HW6 (series + continued fraction), never as 1 − Φ(a), which would lose all digits for large a.

even df = 2m: a finite sum

p = e−x/2 Σk=0m−1 (x/2)k/k!

For df = 2 simply p = e−x/2. For df = 4 (our 3×3 tables) two terms.

any df: incomplete gamma

p = Q(df/2, x/2), the regularized upper incomplete gamma. Below z = a + 1 a power series for P = 1 − Q; above it, a continued fraction for Q directly (Numerical Recipes §6.2). ln Γ by Lanczos. This is the one used everywhere on the page.

The permutation test: a p-value without formulas

Take the n pairs and shuffle the values of F among the units. This destroys any link between X and F (H0 is now true by construction) but keeps both margins exactly. Compute χ² of the shuffled table and repeat B times. The share of shuffled tables with χ² at least as large as the observed one is the p-value: p ≈ (#{χ²perm ≥ χ²obs} + 1)/(B + 1). It needs no large-n approximation and no Cochran rule. The histogram below should follow the χ²df density: that is the asymptotic theory, checked by simulation.

7. Independence in statistics and in probability

The word "independence" is used in two places. In descriptive statistics it is a property of the frequencies of a dataset; in probability it is a property of the model (the population) that produced it. The χ² test uses the first to decide about the second.

In statistics (on the data)

F is statistically independent of X if all the row profiles are equal (and therefore equal to the marginal of F): f(bj | ai) = f·j for every i, j. The following are equivalent:

  1. all row profiles are equal;
  2. all column profiles are equal (independence is symmetric: if F does not depend on X, X does not depend on F);
  3. fij = fi· · f·j for every cell;
  4. nij = ni· · n·j / n = Eij for every cell, i.e. χ² = 0.

Proof of 1 ⇒ 3 ⇒ 2. If f(bj | ai) = f·j, then fij = f(bj | ai)·fi· = f·j·fi·, which is 3. Dividing 3 by f·j gives f(ai | bj) = fij/f·j = fi·, which is 2. Multiplying 3 by n gives 4.

On real data condition 4 practically never holds exactly: the counts are integers and Eij usually is not. Exact statistical independence is an ideal. What we can ask is whether the data are close enough to it, and that is what χ² and its p-value measure.

In probability (on the model)

  • Events A and B are independent if P(A ∩ B) = P(A)·P(B). When P(B) > 0 this is the same as P(A | B) = P(A): learning that B happened does not change the probability of A.
  • Discrete random variables X and Y are independent if P(X = x, Y = y) = P(X = x)·P(Y = y) for every x, y: the joint law is the product of the marginals. In general (also continuous): FX,Y(x, y) = FX(x)·FY(y), and with densities f(x, y) = fX(x)·fY(y).
  • Consequences: E[XY] = E[X]E[Y], so Cov(X, Y) = 0 and Var(X + Y) = Var X + Var Y. HW4 used exactly this to get Var(Sn) = nσ² for the i.i.d. steps of the attacker.

The bridge: the Law of Large Numbers

A relative frequency is an estimate of a probability, and by the LLN of HW4 fij → pij, fi· → pi·, f·j → p·j as n → ∞. So if the model is independent (pij = pi·p·j), the sample becomes closer and closer to statistically independent, and χ²/n → 0. If the model is dependent, χ²/n tends to a positive number (V² times min(r, c) − 1) and χ² itself grows like n.

Trap 1: uncorrelated does not mean independent

Independence ⇒ Cov = 0, but not the other way round. Take X uniform on {−1, 0, 1} and Y = X². Then Cov(X, Y) = E[X³] − E[X]E[X²] = 0 − 0 = 0, yet Y is completely determined by X. With 100 units per value of X:

8. Interpretation

The verdict on each dataset (synthetic ones at n = 500, fixed seed). For the synthetic datasets we know the truth, so we can tell whether the test was right.

If p < α

The data are hard to reconcile with independence: X and F are associated. Look at V for how much and at the residuals for where. You cannot conclude that X causes F (§9), and p says nothing about how large the effect is: that is V.

If p ≥ α

The data are compatible with independence: no evidence of association. You cannot claim that X and F are independent: we fail to reject H0, which is not a proof. With a small n the test may simply be unable to see a real dependence (weak dataset at n = 500).

The p-value is not the probability that H0 is true: it is a probability computed assuming H0.

Experiment 1: on independent data, the test is wrong 5% of the time

α = 0.05 means: when H0 is true we accept rejecting it by mistake 5% of the time (a type I error, a false alarm). Generate many independent datasets, run the test on each, and count:

Experiment 2: on dependent data, p falls with n, V does not

200 datasets for each n, from the dependent and from the weakly dependent model. "Rejections" is the share of the 200 tests with p < 0.05: the power of the test. The last row is V computed on the model probabilities themselves (n = ∞).

  • As n grows the median V settles on the model value (≈ 0.25 and ≈ 0.05): V estimates a property of the population, the strength. For small n it is biased upwards: even under independence χ² is about df on average, so V² ≈ df / (n·(min(r, c) − 1)) from noise alone (with n = 30, df = 4: V ≈ 0.26 for a model with V = 0.05).
  • p falls towards 0 as n grows, for both models: p mixes strength and sample size. The weak dependence is practically invisible at n = 100 (power ≈ 10%, barely above α = 5%) and detected every time from n = 10000. With enough data every non-zero dependence becomes "significant", even one too small to matter in practice. (A p shown as 0 is below 10−308, the smallest number a double can hold.)
  • Missing a real dependence (weak model, small n) is a type II error. The only cure is more data.

9. Association is not causation

A significant χ² says only that the joint distribution of X and F is not the product of the marginals. It is symmetric in X and F (swap rows and columns and χ² is the same), so it does not even have a direction: it cannot say who causes whom. An association can come from:

mechanismcyber example
X causes Fapplying a patch → fewer compromises
F causes X (reverse causation)companies that were breached then install an IDS: "companies with an IDS have more incidents"
A confounder Z causes bothcompany size: large companies have more IDS and more incidents, with no effect of one on the other (built below)
Selection (Berkson's bias)studying only the systems that ended up in an incident report: two independent reasons for being included become associated in the sample
Chance5% false alarms at α = 0.05; run 20 tests on unrelated variables and on average one is "significant" (multiple comparisons)

A confounder built on purpose: IDS, incidents, company size

2000 companies, 1000 small and 1000 large. Large companies buy an IDS far more often (90% vs 10%) and are attacked far more often (30% vs 5%). Inside each size class the IDS changes nothing: the incident rate is the same with or without it (each stratum is exactly independent, χ² = 0). Pooling the two classes:

The aggregated table shows a strong, highly significant association (27.5% vs 7.5% incidents) that would read as "the IDS attracts attacks". It exists only because size drives both variables. Conditioning on the confounder (looking inside each stratum) makes it vanish. This is Simpson's paradox: an association can appear, disappear or reverse when a third variable is taken into account.

The real case: UC Berkeley admissions, 1973

Graduate admissions in the six largest departments, the best-known case of Simpson's paradox (Bickel, Hammel and O'Connell, Science 1975). Pooled, men are admitted much more often than women, and the χ² test is overwhelming. Department by department the gap disappears and in A it even reverses:

Getting to causation

  • Randomized experiment: assign X by coin flip (e.g. install the IDS on randomly chosen machines). Randomization breaks the link between X and every confounder, known or unknown; then an association can only be caused by X (or by chance, which the test controls).
  • Observational data: condition on the plausible confounders (stratify, as above), check the time order (the cause comes first), look for a mechanism and a dose–response relation (Bradford Hill's criteria). This makes causation more or less plausible, never proven.
  • For the synthetic hacker data we can say that the level causes the outcome, but only because we wrote the generator: the causal knowledge comes from the code, not from χ².
  • The other way round, absent confounding and selection, causation does imply dependence, but even an observed independence does not rule out a cause: two opposite effects can cancel out.

10. Conclusions

  • A contingency table is a group-by count of the pairs (xk, fk). Dividing by n, by the row totals or by the column totals gives joint, row-conditional and column-conditional frequencies; the marginals are the distributions of each variable alone.
  • Independence means equal profiles, equivalently fij = fi·f·j; the expected table Eij = ni·n·j/n is what the data would look like if it held exactly, with the same margins.
  • χ² adds up the squared standardized gaps between O and E. Under independence it follows approximately χ²df, df = (r − 1)(c − 1); its right tail is the p-value, computed here with the incomplete gamma function (agreeing with independent references to ~10−15) and confirmed by a permutation test.
  • The independent synthetic dataset is not rejected (and over thousands of repetitions it is rejected ≈ 5% of the time, as α promises). The dependent one is rejected with V ≈ 0.25 (medium for a 3×3 table). The weak one is missed at n = 500 and detected only with thousands of units. The Titanic table gives χ² = 190.4 on 3 df, p ≈ 5·10−41, V = 0.29 (between small and medium): class and survival are clearly associated (62% of first class survived, 25% of third class). The NSL-KDD traffic gives χ² = 5207.4 on 6 df, p below 10−308 (shown as 0), V = 0.32 (between medium and large for a table with min(r, c) − 1 = 2): 83% of the UDP connections are normal, against 16% of the ICMP ones.
  • p measures how surprising the data are under independence and depends on n. V measures how strong the association is and does not depend on n, so a report needs both.
  • χ² is symmetric and blind to mechanisms, so association does not give causation. The IDS example and Berkeley 1973 show an association produced entirely by a confounder, which disappears inside the strata. Causal claims need randomization or extra assumptions outside the table.
